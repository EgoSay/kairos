## 产品目标与当前事实

使用者是维护本人生活记录的 Kairos 用户。任务是方便地改名、合并和整理标签，也能让 Agent 阅读内容后准备整理方案，由本人决定实际变更。

成功信号：常用改名/合并不必逐条打开记录；自然语言整理有明确理由和原文来源；页面与 MCP 的同一操作得到一致结果，失败和冲突不会静默丢失数据。

依据 `BRAND.md`，记录可以不填标签，原话由本人保留和解释，AI 不替本人定义人生。本功能按需进入，不自动整理全部记录，不按低频标签强制删除，不新增复杂分类体系。

当前源码事实：

- `proto/api/v1/memo_service.proto` 的 `Memo.tags` 为 output-only，从正文提取。标签改名会调整实际标签标记，不能只改显示名称，也不能全局替换同名普通文字。
- `web/src/components/Settings/TagsSection.tsx` 管理颜色、内容模糊等显示规则，规则键还支持正则模式；移除规则与从记录移除标签不同。
- 当前 `/mcp/journal` 和专用 Agent 凭据只读；`server/mcp/README.md`、`server/auth/` 及 API 授权层共同限制写入。现有只读凭据必须继续保持只读。
- `server/api/v1/memo_service.go` 的保存涉及版本、SSE 与外发边界。标签维护需要专用业务操作，不能让 Agent 用通用正文更新接口自由改写记录。

## 页面和入口

| 入口/页面 | 用途 | 优先内容与主要操作 |
| --- | --- | --- |
| 侧栏「标签」旁的管理入口；设置内同样可进入 | 易发现的统一管理入口 | 一次进入标签管理 |
| 标签管理页（建议 `/tags`） | 搜索和整理已有标签 | 现有标签树、记录数量；每个标签提供改名、合并、调整层级、移除标签 |
| 记录列表多选状态 | 对指定记录调整标签 | 已选数量、范围说明；批量添加/移除；共同标签与部分拥有标签分别表示 |
| 操作预览 | 决定一次具体变更 | 来源→目标、范围、受影响记录及差异；主按钮显示「确认修改 N 条记录」 |
| 整理建议/操作记录 | 查看 Codex 方案与执行结果 | 理由、代表记录来源、待确认项、执行结果和可用的撤销入口 |
| 设置 → Agent / MCP | 管理 Agent 权限 | 原只读凭据继续保留；另行启用具有效期和撤销能力的标签管理权限 |

首屏不同时展示大量配置。整棵子树、回收站和高级显示规则按需展开；图标、颜色不成为标签整理的必填项。沿用现有 Tailwind 语义样式和 Base UI 组件，不建立新视觉主题或引入大型依赖。

## 第一版范围

1. **改名、合并、层级调整、移除标签**：明确精确标签与整棵子树范围，移除标签不删除记录。目标已存在时使用合并语义，不产生重复标签。
2. **多选记录批量增删标签**：保留每条记录其余实际标签；跨页和全结果选择清楚显示对象范围，不静默扩大选择。
3. **预览和执行记录**：保存前看到受影响数量和逐条差异，执行后可核对成功、失败、冲突及跳过项。
4. **Codex 整理建议**：Agent 阅读获准范围，提出候选映射、理由、来源和不确定项。纯外链等无法判断内容保留待确认，不为凑分类自动迁移。
5. **共用执行能力**：界面与 MCP 使用同一套业务规则、校验、幂等操作和审计结果。

第一版以 Codex 承担语义分析，Kairos 承担方案预览、确认、执行和记录。不以另行配置应用内 AI 服务为前置；自动运行应用内模型的「一键 AI 整理」可在以后单独决定。

## 两种使用流程

### 在 Kairos 中操作

管理标签 → 找到旧标签 → 选择「合并到…」 → 选目标 → 查看范围及逐条差异 → 确认执行 → 查看结果。

列表多选 →「调整标签」→ 添加/移除目标标签 → 预览 → 确认。取消返回原选择，不影响编辑草稿；网络失败保留输入和计划，安全重试。

### 在 Codex 中操作

用户用自然语言指定范围 → Codex 读取标签与相关原文 → 准备合并/调整计划 → 返回建议摘要和 Kairos 预览链接 → 用户在 Kairos 确认该计划 → 执行并返回可核对结果。

建议第一版由 Kairos 预览页承担明确的人类确认：可直接「确认并执行」，也可批准后让 MCP 执行同一计划。两者只能消费同一次确认，重复提交不会重复修改。只批准已经预览的具体对象和映射，不批准之后出现的新记录或扩大范围。

这让当前 Codex 继续提供自然语言入口，确认页只需一次决定。MCP 自己传入 `confirmed: true` 不能替代用户确认；其他记录正文和外链内容均不能构成操作授权。

## MCP 授权与共用操作契约

建议提供四类能力（名称在实现时与现有工具规范对齐）：标签列表/统计、准备变更预览、执行已批准计划、查询操作结果。

- 现有只读凭据仍可读取获准内容，不能获得写入能力。另设限定为本人标签维护的权限，不复用能任意改正文、删除记录的通用 PAT。
- 带标签管理权限也只能提交标签操作；所有 REST、Connect 和 MCP 入口都检查同一范围，不能换接口绕过。
- 计划绑定用户、操作映射、对象集合及记录版本。用户确认后才产生短期有效的执行授权；Agent 无权自行批准或扩大计划。
- 凭据过期/撤销、计划过期、内容发生变化均拒绝执行并提供重新预览路径。新权限字段缺失或回滚到旧服务时拒绝这类凭据，不降级成普通高权限凭据。
- 正常和归档记录默认纳入标签管理；回收站另列数量，可明确选择迁移，但不恢复记录或原分享/外发授权。只读 MCP 当前不可见回收站，预览端必须按实际管理权限重新计算。

新增权限是本次功能的设计范围；实际创建凭据、替换当前 Codex 配置或执行私人记录变更须在相应实现和校验完成后进行，不能借方案评审提前扩权。

## 数据与恢复规则

- 服务端按 Markdown 解析得到的真实标签位置修改标记。保护代码、链接、普通文字和近似标签；嵌套路径按完整段匹配，不误改同前缀的其它标签。
- 保留原始记录日期、非标签正文、其它实际标签、附件、位置、关联、置顶、权限和生命周期状态。标签维护形成可追溯的版本/操作记录，历史版本原文不改写。
- 原子写入内容和派生标签索引；与离线同步和并发保存共用冲突规则，不覆盖预览后新增正文。
- 标签树、计数、搜索、客户端缓存和视图同步。可明确解析的视图标签条件可随迁移更新；复杂表达式/正则规则列出待处理影响，不做文本级替换或静默扩大条件。未解决的依赖不能被标为整体成功。
- 正则显示规则与具体标签单独管理。合并后颜色/模糊设置冲突在预览中说明，不能意外降低已有模糊保护。
- 标签维护不自动触发分享、分区外发或正文 Webhook。必要的 SSE/同步通知继续工作，让客户端获得真实最新状态。
- 执行前保存受控的变更前快照和实际对象清单，结果保留幂等操作标识。撤销只恢复该操作造成的变化；对象随后被编辑时拒绝盲目覆盖，明确列出冲突对象。

## 交互和状态

| 状态 | 行为 |
| --- | --- |
| 加载 | 明确读取标签或生成预览中；不允许基于不完整数量执行 |
| 无标签/无匹配 | 明确空态，可退出或改条件；不混用请求失败 |
| 输入无效/同名 | 就地说明合法名称或引导合并，保留输入 |
| 只读/权限不足 | 可读范围保持；写操作明确说明需标签管理权限，不要求管理员全权凭据 |
| 有不确定项 | 建议与待确认项分开，用户可取消勾选；不自动猜测外链内容 |
| 预览后发生修改 | 具体冲突对象可定位，重新预览，不直接覆盖 |
| 执行中 | 固定确认范围，防止重复点击；退出后可回到操作记录查看状态 |
| 成功/失败/部分失败 | 显示精确数量与对象状态，不把部分完成报成全部成功；按操作标识重试 |
| 撤销 | 显示可恢复对象和后续编辑冲突，保留审计记录 |

键盘：合理的初始焦点和返回焦点、Escape 取消、方向键/搜索选择目标，Enter 不绕过变更预览。窄屏只保留当前任务的主操作，可滚动查看差异；不用颜色作为唯一状态信号。不以动画掩盖等待或保存错误。

## 实现与验收交接

实现责任：标签业务规则放入 `core/` 的对应领域包，API 薄处理器负责授权和响应，存储层负责事务/操作状态；前端复用标签树和选择组件，MCP 复用同一 API。开始实现时先确定现有事务与版本接口的可复用边界，再选择最小持久化方案；如有 schema/proto 变化，按项目流程维护三数据库迁移及生成物。

原型重点：标签列表、一次合并预览、记录多选、Codex 提交计划后的确认页和失败恢复。使用合成数据；不把私人记录正文写入公共 issue、PR 或截图。

最低验收：

- [ ] 改名/合并/移除、多标签、层级边界、重复目标和特殊字符准确，普通文字与代码/链接不误改。
- [ ] 内容与索引同步，原日期、附件、关系、权限、生命周期及其他实际标签无误改，历史版本仍可读取。
- [ ] 视图/显示规则影响可查，复杂表达式不被静默重写，模糊保护不降低。
- [ ] 多选/分页范围、正常/归档/回收站范围与预览一致，预览后新增记录不自动纳入。
- [ ] 网络失败、部分失败、重复提交、离线并发、计划过期和撤销冲突有实际用例与恢复证据。
- [ ] 原只读凭据和其他用户不能写；标签管理凭据不能改正文、删除记录、管理备份、分享或分区；全入口一致拒绝。
- [ ] Agent 不能自行批准计划，权限字段丢失和服务回滚不扩大权限，撤销/到期即时生效。
- [ ] 实际 Kairos 浏览器与当前 Codex 客户端分别完成准备→确认→执行→读回，证明同一操作结果一致。
- [ ] frontend lint/test/build、相关 Go/race 和必要的三数据库/Proto 检查通过；正式上线先完成备份，再核对原服务、原数据及实际版本。

剩余决策：双入口已由用户选定；上述第一版能力和「Kairos 预览页确认、受限标签写权限」仍为待评审建议。当前没有给现有只读 MCP 扩权，也没有实际合并用户标签。
