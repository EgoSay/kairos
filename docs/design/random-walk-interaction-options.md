# 随机漫步：让阅读自然发生

Status: In progress — 2026-10-27。Evan 已确认采用 A+C 连续阅读与可选地图，并授权更新 Issue / PR、实施及 ego lite 验收。本文保留 A/B/C 备选讨论，当前实施以 A+C 为准。沿用现有设计系统、权限、后台关联与缓存契约，最终产品验收待 Evan 完成。

原型入口：[交互试读](prototypes/wander/index.html)。可直接打开 HTML，也可从本地 HTTP 服务访问。所有记录、提示与关系均人工虚构，不连接账户或模型。

## 1. 问题与依据

本轮反馈：每篇相关记录需要点击「沿这条线索走走」才成为完整阅读焦点，用户被迫不断决定要不要深入。

源码现状：`JournalWander.tsx` 对关联记录采用 `line-clamp-3`，下方同时出现关联提示和继续按钮。原文虽然先于解释出现，但候选卡片依然在要求用户选择。旧产品稿 §7 的单击路径也不足以解决「阅读为什么需要反复决策」的问题。

[flomo 的官方说明](https://help.flomoapp.com/advance/random-walk.html)强调沿笔记间的隐约关联游走、允许驻足，以漫步本身为目的；也区分随机遇见与有目的的搜索、标签整理。认知地图用来看主题全貌，可以与漫步配合。本文据此推导 Kairos 的方案，不把官方文字当作其具体手势、界面或算法的实测证据。

Kairos 的约束来自 `BRAND.md`：记录与阅读低负担，原文拥有解释权；不强迫产生洞察、保存路线、写总结；内容与控制权优先于探索与装饰。

**本轮判断：不仅少一次点击，更要少一次「我现在应该做什么」的犹豫。图谱负责安排相遇，正文负责承载体验。**

## 2. 产品模型

- 用户：想偶尔回到自己的生活记录，发现横跨时间和关系的联系，不想先选主题或整理标签。
- 工作：打开就读，在少量有关联的原话中自行体会；有兴趣再看线索、拐弯或返回。
- 成功信号：进入后不用说明就能读到下一篇；不会担心选错方向；能够找回刚才的文字；读一篇就离开也完整。真实体验须由 Evan 判断，不能由点击次数或浏览时长代替。
- 主要风险：默认路径暗示唯一解释；关联提示先于阅读而影响理解；无尽加载制造刷取压力；地图缩小字体、迫使定位；长文截断再次引入打开负担。
- 非目标：本轮不改模型、不重建图谱、不设计全库知识管理工具、不采用某一种方案、不修改正式应用代码。

## 3. 三种备选

| 方案 | 默认动作 | 阅读与关系 | 主要代价 | 适用判断 |
| --- | --- | --- | --- | --- |
| A 顺着读 | 普通纵向滚动 | 原文接原文；两篇之间一行轻提示；岔路可忽略 | 系统安排主要路径，分支全貌较弱 | 推荐作为日常默认 |
| B 翻页并读 | 横向翻页或箭头 | 桌面两篇并排；手机单篇与下一页边缘；日期保留语境 | 手机需要区分纵向读长文、横向翻页 | 偏好对照和明确节奏时 |
| C 原文地图 | 在局部平面上移动 | 所有原文展开，线条表达分支；无需先开卡片 | 空间定位、长文、小屏幕成本最高 | 更适合作为主动打开的地图 |
| A+C 连读与地图 | 默认纵向阅读；想看分支才展开地图 | 原文连续，地图定位；选节点直接回原文 | 地图仅展示定位用原话片段，不适合在里面长读 | 本轮新增组合试读 |

### A：顺着读（推荐）

打开即出现起点原文。相关原文已经接在下面，读到页尾后按日常习惯往下滚，就遇见下一段；不出现候选摘要、展开全文或「继续」闸门。

示例小径：爱情里等待被察觉 → 家人面前终于开口 → 对朋友提出具体陪伴请求。家人那篇旁边有一个低强调的岔路，通向工作里的求助。主路无需处理岔路也能读下去。

一小段小径自然结束，不显示步数、完成率、成就或任务。用户可以回看、离开，或主动换一个随机起点。原型用三篇主路和一篇岔路比较交互；生产数量须由内容长度和关联证据决定，不作为固定推荐配额。

默认小径意味着由系统作一次可撤回的选择，不意味着「最正确的解释」。路径不以停留时长、刷取次数为目标；不能为了不断流而接上没有证据的关系。

### B：翻页并读

把连续小径铺成书页。桌面同时看到两篇完整原文，对照时间、语气和场景；翻一页时保留一篇共同原文，另一篇出现。无需先看预览再打开。

手机采用可原生横向滑动的书页，侧边露出下一页；长文仍纵向自然滚动。提供可见左右按钮和键盘方向键，不能只靠隐藏手势。

它的优势是安静、聚焦、易比较，代价是手机上的双向操作。原型不采用垂直滑动强制切篇，也不把正文塞进独立限高滚动框，避免读长文时误翻页。

### C：原文地图

打开一个稳定的局部区域，原文卡片已展开，旁边的关联原文也已在同一平面。平移即可读，不需要把节点打开成新页面。

概览只用来定位；「居中阅读」恢复可读字号。不会用力导向动画让文字四处移动。原型提供方向按钮、回到起点、看全貌和居中操作，也能用触控板或手机原生滑动。

这种方式保留最强的空间与分支感，但长文会拉长画布，小屏幕无法同时看清地图与原文。因此建议它做 A 的可选地图，而不是所有人的第一屏。这是本轮建议，尚未被采用。

### A+C：连续阅读，按需看看附近

入口：[组合原型](prototypes/wander/index.html#hybrid)。原型外框新增「A+C 连读与地图」，原先 A/B/C 保留作对照。

默认是 A 的连续原文。页头仅保留一个低强调、滚动时仍可触达的「附近地图」入口；地图默认关闭。家人记录旁的小岔路提示也可打开同一个地图，完全忽略它不影响主路阅读。

地图在桌面作为右侧抽屉、手机作为底部面板出现，背景阅读页面保持位置与宽度。当前记录高亮；原文节点、日期、原话片段和连线帮助认出现在的位置、来路与岔路。地图不要求用户先选主题，不自动飞散，不因读到下一篇主动弹出。

组合版将 C 的分支空间关系收进小地图，节点中的短原话仅用于定位，不提供第二套详情阅读器。长文始终在连续正文里阅读：用户主动选中地图里的记录后，一次点击就收起地图并抵达完整原文，无须另点「打开」或「沿线索继续」。

- **只看看地图**：关闭或 Esc 原位返回，原文滚动、展开提示、键盘焦点保留。
- **回看已在主路的记录**：直接定位到原文，提供「回到刚才」。
- **走到工作岔路**：完整工作原文原位接在家人记录后，关系依据仍然可展开。之前主路内容不删除或重排；「回到刚才」恢复进入岔路前的位置与岔路开合状态。
- **换起点**：显式重新抽取，并清理本次返回栈；不会把新随机起点画成上一条的关联。

正文与地图使用同一组节点和关系，地图只响应主动操作。原型的确定性四条记录不代表生产图谱规模；生产仍需限制局部节点、核验资格和来源版本，不能为了地图即时出现而暴露失效内容。地图首次加载失败时连续阅读应保持可用，失败信息与重试限于地图内；空邻域只显示当前原文的位置，不编造分支。

推荐试读：先向下读到家人 → 看附近地图 → 只关闭一次、体会是否打断 → 再选工作 → 直接读全文 → 点「回到刚才」。再打开长文开关，重复地图往返。

## 4. 页面与流程

生产概念路由仍为 `/journal/wander`。入口不新增模式选择页。原型外框的 A/B/C、A+C 切换与长文开关只供评审。

1. 从探索入口进入 → 可读原文直接出现，少量关联原文已备好。
2. A 滚动 / B 翻页 / C 平移 → 阅读下一篇，不触发模型调用、不要求选择主题。
3. 对一句提示好奇 → 原位展开双方原话与场景差别；收起后继续阅读。
4. 想回看 → 「看看来路」只展示本次经过的记录；选择后回到文字，不重抽、不丢失阅读状态。
5. 想换地方 → 「换个起点」是明确的新随机起点，不伪装成与上一条有关系。
6. 想结束 → 直接退出，不要求保存、填写、评分或生成总结。原型结束页的「回到刚才」只用于试读回退；正式应用应直接返回原入口并保留本次阅读状态。

## 5. 交互契约

| 事件 | 反馈与结果 | 焦点、键盘、触控及恢复 |
| --- | --- | --- |
| 进入 | 正文优先，日期与原标签辅助；不用主题标题提前解释 | 键盘能到正文；原文可选中、复制 |
| 读下一篇 | 全文已存在，普通滚动或翻页即可 | 不劫持纵向滚动；不能点正文任意位置就跳走 |
| 看提示 | 一句话原位展开双方引文及差异 | 原生可聚焦 disclosure；Enter/Space；不移动阅读焦点 |
| 提示不贴切 | 隐藏提示，原文保留，提供撤销 | 操作后焦点落在撤销；不静默丢掉整条阅读记录 |
| 拐弯 | 只在主动选择时展示侧路原文 | 保留主路与原位置；不强制先保存路线 |
| 返回 | 恢复原顺序、滚动和提示展开状态 | 不重新请求生成；来路对话框支持 Esc 和焦点恢复 |
| 后台有更新 | 当前阅读内容不被突然重排 | 后续进入采用新结果；权限撤回例外，必须即时隐藏已知失效内容 |
| 运动 | 字符出现不用等待过渡结束，无自动翻页或飞散 | 遵循 reduced-motion；不用视差、自动滚动、强制吸附长文 |

**长文也是正文。** 原型的长记录无需展开，目的是检验真实阅读成本。生产可按段渐进取回，但应提前在阅读到达前准备，保持原顺序与连续滚动。网络不足时在正文尾部原位告知，不能又退回「点开全文」；极长内容及附件加载还须结合真实记录分布验证预算。

## 6. 状态矩阵与顺滑约束

| 状态 | 用户看到什么 | 恢复与约束 |
| --- | --- | --- |
| 可读 | 原文直接出现，已有关联可直接读 | 无实时模型等待；有限预取，不下载全库 |
| 初次打开、未命中缓存 | 保持阅读版式的轻占位；尽快出现有效原文 | 不显示知识图谱构建进度占据阅读区；已授权处理在后台继续 |
| 有原文、暂无可信关联 | 仍能读这一篇；温和说明附近暂时没有线索 | 可换起点；不能用无关内容填空 |
| 没有合格原文 | 直接空态，允许退出 | 不逼用户先选标签或完成任务 |
| 模型未开启或正在准备 | 可展示有效原文；未开启时不声称已有语义关系 | 开启行为继续遵循已有明确同意与账户配置；不借原型交互绕过授权 |
| 下一段未取回或失败 | 已读原文保持稳定，在需要的位置轻提示 | 原位重试；不全屏清空，不自动跳到别处 |
| 断网、会话待核验 | 遵守现有资格核验与撤回规则 | 不为零等待复用未经核验的私人缓存 |
| 来源删除、排除或权限撤回 | 从正文、来路、预取中移除相关内容 | 避免旧提示继续暴露原话；资格检查优先于预取速度 |

视觉顺滑与加载速度分开验收。原型全为本地静态数据，不能证明正式应用达到冷启动或长文性能指标。生产仍需：轻入口、原文与邻域一次有界返回、下段提前取回、附件稳定占位、没有布局跳跃、缓存按来源版本失效。选定交互后再测真实构建；原先冷启动未达标事实仍然有效。

## 7. 原型范围、评审与下游

本轮只做可比较的原型：三种阅读动作、可展开提示及撤销、来路跳转、换起点、退出恢复、长文、桌面和手机布局。未接入模型、账户、反馈接口、失效订阅或生产级持久路径。

最重要的评审问题：

- 打开后是否自然知道怎么读下去，还是先研究控件？
- 读到第二篇时，有没有被系统提前告知「你应该得出什么」？
- 偶尔想拐弯、返回或停下时，是否仍然轻松？
- 手机长文是否改变了对方案的偏好？

推荐 **A 作为默认阅读，C 的局部地图作为以后可主动打开的辅助视图**；B 保留为独立备选。不要把三个方案全部塞进正式产品的模式选择器。

### 已批准实施范围

前端 owner 以 `JournalWander`、`useWanderTrail`、`WanderMap` 和 `WanderConnection` 承接 A+C；复用 `JournalMemo` 的完整原文、附件及主题，新增连续阅读模式，不改变其他页面的折叠行为。地图使用现有 Sheet 的阅读尺寸与 Base UI 焦点管理；不添加可视化依赖。

主路默认准备三篇，显式岔路最多十二篇，本次返回最多十六处；数量为首版有界读取和内存预算，不展示为任务或进度。会话仅保存标识和位置，不保存私人正文与证据；原文、提示与地图仍从当前资格与版本的查询结果派生。撤回、模糊标签、跨 epoch 结果、被隐藏的关系和断网状态均须关闭相应展示。

质量验证覆盖连续原文无点击闸门、长文与媒体、真实边衔接、来路恢复、桌面/手机地图、键盘与焦点、模糊标签、撤回和断网恢复。先在独立虚构笔记库交付本地实例，最终由 Evan 验收；原来的 Cloudflare 联调及冷启动未达目标事实继续保留。

### 本轮原型验证

2026-10-27，使用 ego lite，同一 TaskSpace 64 的 p3 原型页；p1 的正式功能本地验收页保留。结果：

- A：三篇主路正文直接存在，默认提示收起；展开双方引文、隐藏不贴切提示、撤销、岔路展开、来路对话框与 Esc、结束后恢复已展开状态均通过。
- B：桌面两篇并排，前后翻页与方向键通过；390px 下用浏览器合成触控横滑，书页实际横移 308.5px。
- C：概览缩放、恢复原字号、居中和回到起点通过；390px 合成触控平移实际横移 271px；长记录高度 1168px 时四张正文卡无重叠。
- A 长记录：六段全文，无额外展开操作；390px 正文可见高度与内容高度均为 987px，未截断。320/768/1440px 页面无横向溢出，减少动态效果媒体偏好可生效。
- 修复并重新加载验证了反向起点的岔路重复问题，四篇展示来源保持唯一。
- 三种方案的桌面、390px 截图已查看。JavaScript 语法检查、文件链接检查、`git diff --check` 通过。只改变独立原型和设计文档，未运行或宣称正式应用 CI 验收。

这些检查只确认原型能操作和排版可读，不代表真实触屏设备手感、关联质量、生产性能或 Evan 已选择某个方案。

### A+C 补充验证

同日以 ego lite TaskSpace 64/p3 验证 HTTP 入口及本地 `file:` 入口。1440px 桌面右侧地图、390px 底部地图的截图已查看；320px 下页面无横向溢出，返回、地图与关闭按钮仍可触达。

- 默认地图关闭，三篇主路直接可读；六段长记录不截断。
- 读到家人后打开地图，当前节点正确高亮；关闭 / Esc 后滚动值与原文屏幕位置偏差均为 0，展开提示和焦点保留。
- 一次选中工作节点即回到三段完整原文，没有第二个打开步骤；桌面与手机「回到刚才」均恢复原位置，测得偏差 0。
- 工作岔路之后切换为工作与朋友之间的真实示例关系；回到主路恢复原先家人与朋友的提示。两套展开状态分别保留，不沿用错误的前一篇语境。
- 键盘 Enter 选节点可返回原文；原有 A/B/C 仍可切换，页面无横向溢出。

上述位置数值来自静态虚构原型的浏览器检查，不作为正式应用性能或真实关系质量结论。
