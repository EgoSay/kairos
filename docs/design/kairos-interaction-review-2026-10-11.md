# Kairos 日常交互改进评审

Status: Implemented — 2026-10-11。此文件冻结为已批准设计；工程与发布证据见 `docs/operations/kairos-1.2.0-interaction-verification.md`，不代表个人体验已确认。

日期：2026-10-11（Asia/Shanghai）。依据：用户本轮反馈、`BRAND.md`、1.1.0 线上界面、当前源码及下方官方资料。文中的操作和性能数字是拟定验收目标，不是已经达到的结果。

## 产品模型

面向随手记录生活、日后找回片段的个人用户。一次使用的目标是留下或找到一条记录；无需理解 Markdown、查询表达式、经纬度和关系模型。

采用现有哲学的取舍顺序：数据与隐私 → 本人控制权 → 记录的低负担 → 找回与阅读 → 探索 → 装饰。

这次需要改善的是用户完成任务的过程：默认路径直接、结果及时出现、附加信息随用随添、误操作可撤回。自动处理格式不意味着改写原话、自动关联、自动定位或自动对外发送。

成功信号：不看说明即可完成关键词查找、图文粘贴、关联旧记录和添加常用位置；任务过程中不要求切换文本模式，不反复确认同一选择。工程通过与本人体验确认分开记录。

范围覆盖 R02/R03/R04/R05/R06/R12 的交互重整。继续使用现有记录、权限、附件和检索能力；没有新增 AI 供应商、公开发布、后台定位、协作知识库或复杂页面排版需求。

## UX01：打开搜索，就能开始找回

**推荐：一个输入框，输入即有候选；筛选是结果旁边的选择，不是单独填写的表单。**

流程：点“查找记录” → 输入“散步” → 下方直接出现匹配片段 → 点选打开。无需按回车才能得到反馈。

- 空输入：最近查找/最近查看的小列表，以及“未添加标签”“有图片”“日期”快捷条件。仅显示本人当前授权范围，不预加载私人正文到公共界面。
- 输入后：优先展示 5–8 条记录，包含原日期、命中附近的正文、少量标签；关键词高亮。匹配标签作为单独的少量候选，明确标为“标签”，避免与正文记录混淆。
- 点“未添加标签”立即刷新结果。关键词与条件可以叠加，已选条件用可移除的小标签展示。日期先提供最近 7 天/本月，自定义范围在两个端点有效后生效。
- 默认不需要“文本/高级搜索”模式。保留现有高级表达式能力，移至“更多筛选 → 高级表达式”，与普通关键词明确区分，不误把普通文字当表达式执行。
- 全局查找默认本人正常记录，归档可选；在标签或日期视图内筛选时，范围明确显示为可移除条件。不要让隐藏的旧筛选导致“搜不到”。权限仍由服务器裁决。
- 候选不足以展示全部时提供“查看全部匹配记录”，进入可分页列表并保留条件。未得到准确总数时不显示虚构的“共 N 条”。
- Enter：没有主动选中候选时查看全部；用上下键选中后打开该条。Esc：先关闭候选，回到原入口。返回列表或编辑器时保留搜索词、筛选、滚动和草稿。
- 输入约停顿 200 毫秒发起查询；中文输入法组词时不提交未完成字符。取消或忽略旧请求，迟到结果不能覆盖新查询。
- 主列表与候选共用检索规则：中文、特殊字符、父子标签、本人权限、原始记录时间及分页边界一致。候选默认按记录原日期倒序，先保证稳定可解释；不在本轮引入不透明 AI 相关性排序。

移动端采用能容纳键盘的搜索层，输入、结果和返回均在一个上下文；不叠加二级大弹窗。

## UX02：用户只面对一份内容

**推荐：默认就是可直接编辑的阅读效果；普通文字、Markdown、网页富文本和图片都是输入来源。**

| 用户动作 | 应有结果 |
| --- | --- |
| 粘贴普通文字 | 保留文字与换行，光标落在粘贴末尾 |
| 粘贴清晰的 Markdown | 标题、加粗、列表、引用、代码和表格在原位置直接呈现，不先询问模式 |
| 从网页或文档复制带格式的内容 | 保留段落、强调、列表和链接等语义，使用 Kairos 自己的字体与颜色，不复制网页布局 |
| 粘贴图片或图文混合 | 图片留在正确插入位置，出现本地预览与上传状态，用户继续写作 |
| 粘贴当前实例的记录链接 | 提供一个轻量“关联此记录”动作，不自动建立关系 |
| 只想保留字符 | 使用常规纯文本粘贴快捷键或粘贴后的“保留纯文本”，不需要预先打开粘贴模式 |

交互约束：

- 首页不再常驻“Markdown 源码/纯文本粘贴”。源码入口保留在更多菜单里，作为可选的精确编辑/兼容工具，普通任务无需进入。
- 点击加粗文字应直接编辑文字，不因光标进入就整行切换为源码或引起段落跳动。选中文字后出现短格式工具条；常用格式通过“格式”入口和快捷键可达，移动端不依赖悬停。
- 粘贴优先采用明确的语义格式；HTML 与纯文本并存时按来源内容选择可靠表示，不把两份内容重复插入。`#标签` 与 `# 标题`、普通星号、编号与代码按语法边界处理；有歧义保留原文，不自作主张改句子。
- 格式转换与粘贴作为可撤销的动作；撤销/重做、选区、中文输入法、聚焦切换和离线草稿构成同一套连续编辑状态。
- 自动渲染不调用 AI、不润色正文、不自动读取第三方链接。远程图片与剪贴板中的真实图片文件区分处理；仅有外部地址时不假装原件已保存在 Kairos。
- 上传失败保留预览和“重试”，明确尚未上传；不显示“已保存”掩盖未完成的附件。离线继续使用现有草稿和重试能力。

**旧内容兼容是实现门槛。** 未修改的记录保存往返应保持原文；不支持的旧语法/扩展不得静默丢弃或扁平化。旧附件、标签、导出和 MCP 仍使用现有兼容契约。

当前基于源码装饰的编辑方式是否能满足“直接编辑且不显露整行语法”，需要用真实交互原型验证。先用旧内容、输入法、选区、粘贴和撤销测试评估现有实现；若达不到才评估替换编辑核心。不能靠隐藏模式按钮冒称已完成，也不在本评审预先批准重型依赖或存储迁移。

## UX03：关联像选一条旧记录一样自然

**推荐：点击编辑器下方“关联”，就地打开轻量候选层，选择后立即回到写作。**

- 打开即有最近记录与一个搜索框，输入即时筛选；候选包含日期与两三行正文，预览在同一层展开。
- 点某条即加入草稿，收起候选并恢复光标，不再要求第二次“确认关联”。正文下方出现可移除的关联条目。
- `[[` 作为可选键盘快捷入口，使用同一个选择器；不把快捷语法作为使用门槛，不引入与既有人物提及冲突的 `@` 语义。
- 关联自己的已归档记录时显示“已归档”；自关联、重复关联、回收站与无权记录保持现有禁止规则。
- 只在记录成功保存后提交关系。移除关联只删除关系，不删除原记录；保存失败时草稿中的选择仍保留。
- 记录详情展示双向关联，打开后可返回原处；与“分享”“同步到外部”完全独立，不因为关联扩大权限。
- 不默认分析正在写的私密正文来强推 AI 关联，也不自动关联相似记录。

共用 UX01 的候选展示、键盘逻辑和查询能力，但“打开记录”和“选为关联”的动作文案明确区分。

## UX04：先记住在哪里，再按需精确到地图

**推荐：点“位置” → 点常用/最近地点 → 完成草稿选择。地图是辅助校准工具。**

- 第一层只展示常用地点、最近使用和“使用当前位置”；常用地点点一次立即添加，变成正文下方可修改/移除的小标签。
- 输入名字先即时匹配自己的地点。支持“只记地点名”，例如“家”“楼下咖啡店”：没有坐标就明确只保存名称，不伪造 `(0,0)`，地图视图不展示不存在的点。这是本次新增语义，需要实现时核对各驱动、导出和 MCP 的兼容性。
- 地图在“搜索地图上的地点/调整位置”时才展开。选中公开地点已完成选择，重复“确认这个地点”的步骤可以省去；拖动地图时保留“使用此位置”，避免浏览地图就误改草稿。
- 仅在用户点“使用当前位置”后请求定位。定位成功给出可核对候选；低精度、名字不确定或只有坐标时如实表达，不自动贴上猜测的店名。
- 被拒绝、超时、设备无坐标时，就地提示“暂时无法获取位置，可以选常用地点或输入名字”，不弹出阻断写作的报错。
- 用户已手选地点后，迟到的定位/名称解析响应不覆盖它。添加到草稿可以直接撤回；随正文统一保存。
- 收藏管理、修改名称、经纬度编辑放到次级入口，不在每次添加地点时展示；修改常用名称不回写历史记录。

地点检索与记录检索不是同一种服务：当前代码默认公共 Nominatim，其[使用规则](https://operations.osmfoundation.org/policies/nominatim/)禁止自动补全，且限制整个应用最多每秒一次请求。第一轮保持本人常用/最近地点即时筛选，公共地点搜索由用户明确触发，并保留服务端限流、缓存与归属说明；若需要全国 POI 的逐字候选，需要另行选择支持此用途的供应商，费用与隐私范围单独评审。不会把后台成本、密钥输入或服务商选择搬进日常编辑器。

## UX05：一个主动作，其余随上下文出现

推荐编辑器结构：

```text
写点什么……                                      聚焦

在这里直接输入或粘贴，看到整理后的内容。

[已选位置 ×] [已关联的记录 ×]       ← 有内容才显示

照片   关联   位置   更多                 私密 · 保存
```

- “保存”为主动作；标签、分区、日期、录音仍可进入，未选状态不占据大块表单。
- 聚焦入口仍直接可见，不重新藏回更多菜单。进入聚焦改变可用空间，不建立另一份内容或丢失编辑历史。
- 已选择的信息就地展示、修改和撤回；不要把隐藏更多功能误当作降低复杂度。
- 需要注意的隐私/外发状态不能隐藏：若记录会同步到外部，目标与“保存并同步”必须明确。自动保存草稿与正式保存记录分开反馈。
- “最近删除”“备份”“MCP”等管理能力保持原页面，日常记录界面不增加新的设置负担。

## 屏幕与状态契约

| 场所 | 首要内容与动作 | 返回/退出 |
| --- | --- | --- |
| 列表首页 | 编辑正文、保存；全局查找入口 | 草稿保留，滚动不意外重置 |
| 搜索层 | 输入、匹配记录、快捷条件 | 关闭返回原入口；全部结果沿用条件 |
| 全部结果 | 完整分页与明确筛选范围 | 返回候选/原视图保留状态 |
| 编辑器内关联层 | 候选、搜索、就地预览与选择 | 选中/取消后恢复原光标 |
| 编辑器内位置层 | 常用、最近、搜索或只记名称 | 选择即回到正文；地图可单独取消 |

| 状态 | 搜索/关联 | 编辑/粘贴 | 位置 |
| --- | --- | --- | --- |
| Loading | 延迟出现轻量加载反馈，明确哪些是旧候选 | 图片占位跟随插入点，正文继续编辑 | 请求中的状态可取消，不阻塞正文 |
| Empty | “没有匹配”，保留条件并提供清除/扩大范围 | 邀请写作，空记录保存禁用且原因可达 | 没有常用地点也能输入名称 |
| Error | “暂时没能搜索”与“没有结果”区分，可重试 | 保留内容/失败图片，给重试或撤销 | 提供手动名称、常用地点等直接退路 |
| Success | 点结果即可打开/关联 | 保存有明确完成反馈，不追加填写任务 | 地点成为可移除的小标签 |
| Disabled | 无效日期不提交；不能选自己/重复项 | 提交中防重复；明确未传完附件状态 | 无有效选择时禁用地图确认 |
| Permission | 不泄露无权条目与统计，失效后停止展示旧私密候选 | 保存权限失效保住本人本地草稿并提示 | 未主动请求不弹定位；拒绝不反复弹窗 |
| Recovery | 重试保留关键词和条件，旧响应不能回写 | 刷新恢复草稿与上传队列，撤销可用 | 迟到结果不覆盖手选；移除不改变历史 |

键盘：中文组词期间不提前选择/提交；上下键候选、Enter、Esc、Tab 行为一致。鼠标无需悬停才能发现主要动作。触屏关键点击目标不少于约 44px，软键盘出现后搜索结果与保存入口可达。动效只解释展开与收起，不使编辑区跳动；尊重减少动态效果偏好。

| X09 | 离线、上传失败、保存失败与刷新 | 内容和附件状态可恢复；不重复上传、不假报保存成功，不意外外发 |
| X10 | 真正的首次操作体验 | Evan 不读说明完成查找、粘贴、关联、位置四项任务；记录犹豫/误点/需要解释的地方，作为修订依据 |

不以按钮数、自动化通过或原型好看替代 X10。手机视口只能证明布局，真机输入法、系统剪贴板和定位体验仍按实际设备证据记录。

## 原型与实施顺序

本轮交付一个仅含虚构数据的交互示意，供体验输入候选、格式呈现、关联和地点选择的节奏。它不访问生产 API、不保存真实记录，不是最终编辑核心与手机硬件验收。

本次已在 Ego Lite 检查示意：不按回车输入“散步”出现候选，示例内容呈现标题/强调/列表，选择关联后生成可移除条目，点击“家”后关闭地点层并生成地点条目；桌面与 390px 窄屏截图已目视检查。上述仅验证示意的操作与布局，不计入 X01–X10 的生产功能验收，也不代表原生剪贴板、输入法和手机硬件通过。

推荐顺序：

1. 评审这五项默认交互，再用代表性复制来源和旧记录建立真实编辑原型，优先验证风险最大的 UX02。
2. 实施统一即时检索与候选选择器（UX01），直接复用于关联（UX03）。
3. 将通过兼容验收的编辑器交互、粘贴与工具层级一起交付（UX02 + UX05），避免只藏按钮。
4. 简化地点选择和只记名称语义（UX04），补位置失败与恢复验收。
5. 完整可靠性回归 + Evan 无说明操作体验；获得本轮实施授权后按现有备份、版本标签与 Dokploy 流程交付。

下游责任：主实施负责共享检索与编辑状态，前端实现承接本交互契约，质量验收覆盖状态、权限、兼容和真实浏览器行为。优先复用 Base UI 和现有数据接口；本轮不批准新增重型依赖、数据库迁移或付费地图供应商。

评审决策：UX01–UX05 均推荐采用。需要先取得证据的技术未知项是编辑核心能否满足无模式编辑与旧文无损；全国 POI 自动补全是另行选型项。现有功能说明与个人体验清单保留，本文件不改写已经冻结的历史设计。
