# 随机漫步：沿着记录发现关联

Status: In progress — 产品方案 v0.2，2026-10-27；产品方向与 Cloudflare 模型方案已确认，进入开发及本地验收，尚未实现。跟踪：[Issue #38](https://github.com/EgoSay/kairos/issues/38)。

已确认的方向：

- 后台服务自动建立并维护记录之间的关系，用户不需要先选择探索范围、标签或主题。
- 点击随机漫步，直接遇见图谱中的一个节点，以及和它有关的原记录。
- 原文先呈现，旁边附一句可展开的关联提示；解释权属于本人。
- 即时打开、连续浏览顺滑是核心体验要求，需要落实为数据准备方式和可测量的指标。

v0.2 修正：取消 v0.1 的首次范围选择、进入后才分析、离开就停止整理，以及“先预览、再点沿线继续”的主流程。后台准备与前台阅读分离。具体布局、性能预算和分期是本稿建议，尚未通过真实实现与用户体验验证。

本稿为已确认的产品输入；实现遵循[技术方案](random-walk-technical-design.md)，通过本地工程验证后由用户验收。本稿不代表后台服务已启动或生产笔记已处理。

## 1. 产品定位

用户照常记录，Kairos 在后台整理记录间的联系。想回看时，点开便能遇见一段原文，沿着附近的联系继续读，也可以随时离开。

目标用户有零散、跨时间、常常没有标签的生活记录，希望发现其中自己未注意到的联系，同时保有自己的理解过程。维护分类、选择检索范围和等待分析不属于日常漫步的必要操作。

| 入口 | 主要需要 | Kairos 的体验边界 |
| --- | --- | --- |
| 每日回顾 | 重新遇见一些旧片段 | 保留既有少量、同日稳定的原文；可以从其中一条进入漫步 |
| 随机漫步 | 看见记录之间还能怎样连接 | 随机起点、自动关联、局部地图、连续阅读 |
| AI 洞察 | 围绕一些记录进一步思考 | 用户明确发起，对可查看的来源提出观察与问题 |

三者可以接续使用，但不设置必须完成的漏斗。读到一条原文就离开也是完整使用，不要求生成洞察、保存路线或写一篇总结。

成功信号：本人发现一条原先未注意的联系，能回到原文看依据，也能轻松否定牵强的建议。节点数、停留时长、连续使用天数不替代这个目标。

| 随机漫步从一条笔记沿关联走向另一条，漫步本身有价值，不要求产出 | 让“下一段值得读的原文”自然出现，不做探索任务或进度条 |

| 2024 年度信强调帮助历史笔记的意义浮现，AI 在底层支持体验 | 自动准备能力承担复杂工作，用户主要感知到阅读和发现 |

| 设计理念强调自然发生、克制表达和尊重用户 | 保持安静，不用持续生成、提醒或宏大结论制造存在感 |

公开材料没有证明 flomo 使用何种图数据库、后台预计算机制或延迟指标。下文服务结构、缓存策略和性能目标是 Kairos 为满足本次需求提出的方案。

## 3. 与 Kairos 原则的衔接

- 保存一条记录就完成了这次使用。后台整理异步发生，不增加必填字段，也不拖慢保存。
- 平凡、重复、矛盾、间断都可以进入漫步。系统不把所有记录解释成成长轨迹，不因没有连接而贬低某条记录。
- 后台负责提出可查证的联系，本人决定是否有意义。系统建议与本人手动建立的连接保留不同来源。
- 回顾仍由本人主动进入；后台更新不会新增通知、打卡、催促或未完成状态。
- 默认私密。探索范围是本人合格记录，设置中可暂停或排除；日常入口没有范围选择步骤。

现行 BRAND.md 第三条写的是 AI 在主动选择来源后提供阅读角度，core/journal 的说明也明确当前不运行全库自动分析。本次是对这条能力边界的明确扩展。未来实现时应同步调整为“后台自动整理记录间的联系；本人决定何时阅读、如何解释，并可控制处理范围与服务”。本轮保持现有能力说明真实，不提前宣称功能已存在。

## 5. 后台维护什么

对用户而言，这是随记录生长的个人关系图谱。产品对象保持简单：

| 对象 | 内容 | 约束 |
| --- | --- | --- |
| 原记录节点 | 原文、记录日期、原有标签与附件 | 原文是事实来源；生成摘要不能代替原话 |
| 主题／问题节点 | 如“亲密关系”“如何表达需要” | 从多条记录中形成的阅读视角；可交叉、可变化，不自动写成本人标签 |
| 建议连接 | 两条记录为何值得并读 | 有来源摘录、关联类型与版本；语义相似本身不足以成为结论 |
| 已有连接 | 本人添加的引用、手动关系 | 与系统建议分别标明，不能被模型覆盖 |
| 可直接阅读的一组结果 | 起点原文、附近记录、提示、展开依据、局部布局信息 | 后台提前准备，按账户和来源版本发布 |
| 本次路径 | 实际读过的节点、分支、阅读位置 | 支持返回和改道，不要求保存 |

一条记录可以同时落在爱情、家人、表达需要等视角里。主题不是互斥目录，也不要求用户先给每条记录确定唯一归属。

关联可以包括：同一问题的反复出现、不同场景中的相似顾虑、不同时间的说法、相互补充的经验。尤其要避免仅按共同关键词连线，导致爱情只找到爱情、工作只找到工作。

## 6. 自动整理与即时读取

### 6.1 写入之后自动更新

    保存／编辑记录
          ↓
    提交成功，可靠登记待处理版本
          ↓
    后台增量发现候选、核验关联、更新主题
          ↓
    提前准备原文片段、短提示、展开依据和邻近节点
          ↓
    发布新的可读版本
          ↓
    用户点开随机漫步，直接读取

- 写入成功不依赖模型调用。任务可恢复、可去重；同一条连续编辑只处理需要保留的最新版本。
- 初次建立时分批覆盖已有记录；以后优先处理新增、修改与受影响的邻近记录。无需每次全库重算。
- 先用语义与已有结构召回小批候选，再核验是否值得并读；避免对全库所有记录两两生成解释。
- 主题整理可以批量进行。一个节点发生变化，不使整个可读图谱进入“重新分析中”。
- 工作进程重启后能续跑；限流与失败按实际原因退避，避免持续占用保存和阅读资源。
- 逻辑上有独立的后台处理能力；可以先在现有 Go 服务中实现受控任务执行，不预设必须新增微服务或重型图数据库。

### 6.2 阅读时已经准备好的内容

日常点击路径只做必要的账户、来源有效性检查及有界数据读取。语义计算、模型生成、主题聚合不进入首屏、切换节点或展开提示的等待链路。

每组可读结果至少包括当前原文、少量邻近原文、关联短句、可展开的双方摘录、来源版本，以及稳定布局需要的结构。展开“为什么有关”读取已准备的依据，无需再发起生成。

原文较长时，首屏采用保留上下文、明确省略位置的原文片段，全文按需读取；不能以生成摘要冒充原文。附件渐进加载，图片尺寸先占位，不推挤正在阅读的文字。

### 6.3 提前准备与连续浏览

- 主应用已可读、可记录后，低优先级预取漫步页面资源和一组有效起点；点击入口无需再启动完整准备流程。
- 当前节点出现时，预取直接相邻节点的下一片内容，以及少量“换个起点”的备用结果。设置数量和字节上限，不递归下载全图。
- 已访问节点保留阅读位置、展开状态和局部布局。返回直接恢复，不重新抽样。
- 新图谱版本在后台构建，完整后发布；旧版本中仍有效的区域可以继续读。重建不能先清空可用内容。
- 浏览时不因后台新结果到达突然换掉正在读的原文或重排候选；后续进入或新展开时采用新结果。
- 快速连续点击以最后一次操作为准，迟到的请求不能覆盖新的焦点。

缓存必须受账户与来源撤回机制约束。服务端每次返回前检查资格；客户端接收失效事件并移除相关内容，重新连接和恢复会话时先核对版本。首版不永久缓存私人正文到浏览器离线存储。断联期间已显示内容无法被远程即时收回，恢复后必须重新校验，不能宣称无网络时也能保证即时撤回。

## 7. 用户实际看到的流程

### F01 点开随机漫步

直接出现一条原记录、日期和周围少量有关记录；“亲密关系”等主题作为附近的方向线索出现。页头保留返回和“换个起点”，不出现选标签、选时间或开始分析的表单。

起点在合格节点中选择，适当降低近期重复出现的概率，兼顾时间与主题分布。不能只抽连接最多的记录，让平凡、孤立的记录永远消失。无关联的记录仍可阅读，并可换起点。

首屏优先完整表达一段原文。默认两到四个关联方向作为原型布局预算，数量随证据变化，不为填满界面硬凑。

### F02 点击附近记录

点一次原文卡片或地图节点，这条记录立即成为阅读焦点，并呈现它附近的记录。上一条保留在路径中。无需先预览、关闭，再点击另一个“继续”按钮。

全文展开、附件查看和关联提示展开仍是独立的局部操作，不会意外改动探索焦点。可复用现有原位阅读器；其它页面的链接阅读行为不在本次改动范围。

地图采用稳定的局部布局：当前节点、来路和少量可走方向。切换时尽量保留已出现节点的相对位置，避免整张图不断飞散、重排。短过渡帮助辨认位置，内容无需等动画结束才可读；尊重减少动态效果设置。

### F03 自己决定是否看提示

候选原文旁有一句提示，例如：

> 这两段都写到了开口表达需要，顾虑似乎不同。

不展开时，用户可以只读原文、自行体会。展开后显示两端准确摘录、日期、联系所在及必要的场景差别，并可直接打开来源或选择“这条联系不贴切”。

示例均为虚构：一条写“希望伴侣能自己明白”，另一条写“没有告诉父母，怕他们担心”；进一步可能连接到工作中“不好意思向同事求助”的记录。候选线索是表达需要时的不同顾虑，不据此诊断人格或推断共同心理成因。

### F04 回到岔路或换个起点

返回恢复上一节点、原文滚动位置和已展开提示。返回后可以改走另一条，之前走过的分支仍在本次路径中。

“换个起点”直接呈现另一处已准备好的记录；它明确是新的随机起点，不伪装成上一条的关联。没有可信跨主题连接时，允许这个方向到此为止。

### F05 想再深入一点

在读过几条后，可以主动进入 AI 洞察。带入当前本人选择的记录并清楚列出来源，用户可调整后发起。洞察的生成等待留在洞察功能内，不阻塞漫步。

保存路线作为后续能力：保存来源顺序和本人选定的关联，不自动生成一篇日记，不把生成解释反哺为原始证据。首轮重点先验证发现质量与即时阅读。

## 8. 页面与交互约定

桌面采用原文主阅读区和可收起的局部地图。手机先显示原文与邻近片段，轻量地图可展开；任何路线都能通过普通按钮或列表访问，不靠缩放、拖拽或悬停才能操作。

沿用现有纸张表面、松绿强调色与原文内容字体。关系说明在视觉上弱于原文，不展示人格标签、置信百分比或大段默认展开的系统总结。

| 操作 | 反馈 | 状态约定 |
| --- | --- | --- |
| 点击漫步 | 直接出现可读原文和附近记录 | 不先展示配置或分析面板 |
| 点记录卡／地图节点 | 切换阅读焦点，展示附近内容 | 加入实际路径；迟到请求不能回跳 |
| 展开全文或附件 | 原位阅读 | 不推进路径，关闭恢复触发位置 |
| 展开关联短句 | 就地显示已有证据 | 不调用模型，支持键盘与 aria-expanded |
| 点主题／问题节点 | 展示支持该视角的原文与分支 | 是漫步中的可选路线，不变成全库标签筛选 |
| 返回 | 恢复原文、位置、分支和展开状态 | 不重新随机，不清空其他已走分支 |
| 否定联系 | 隐藏该建议并提供撤销 | 持久记录；不修改原文或手动关系 |
| 换个起点 | 直接换到已准备的新位置 | 来路可返回；不伪造连接 |
| 退出 | 正常离开 | 后台整理继续；无未完成提示 |

本次路径默认是临时会话；跳往详情再返回时保留，刷新可保存节点标识再校验恢复，不写入正文快照；登出或切换账户清除缓存。浏览器返回遵循实际阅读历史，同时保留明确退出入口。

## 9. “瞬间打开”的性能合同

以下为建议验收目标，尚无实现测量。不能把演示原型或本机缓存的速度当成最终性能。

| 场景 | 建议目标 | 测量边界 |
| --- | --- | --- |
| 主应用已打开、有效起点已预取 | 点击至首段原文和可操作邻近内容显示，p95 ≤ 100 ms | 计入点击、状态切换和实际渲染；不能只测接口 |
| 相邻内容已预取，切换／返回／展开依据 | p95 ≤ 100 ms；持续交互以 60 fps 为目标 | 原文先可读，不能等待过渡动画 |
| 后台已准备、浏览器没有该组缓存 | 点击至首段与邻近内容可用，p95 ≤ 800 ms | 参考环境 RTT 100 ms、下行 10 Mbps、中档手机；含页面资源 |
| 已登录的全新应用冷启动并直达漫步 | p95 ≤ 1.5 s | 首屏文本目标；网络按上一行，不把手工登录和附件下载计入 |
| 漫步有界读取接口 | 服务端 p95 ≤ 100 ms | 含权限、来源有效性和序列化；不含公网传输 |
| 首屏数据 | 压缩后 ≤ 100 KB | 原文片段、提示、证据和局部结构；全文、媒体另取 |
| 新增或修改后关联更新 | 服务健康、无积压时 p95 ≤ 2 min | 更新异步；初次全库整理单独计时，不承诺同样速度 |

即时性来自提前准备和有界读取，不来自隐藏加载过程。短暂缺失预取时立即给点击反馈，保留上一条已可读原文；相关区域显示真实加载状态，不用全页遮罩阻断阅读，不规定必须展示固定时长的骨架屏。

初次全库建立尚未完成时，直接呈现已有可读原文和已准备好的局部区域，轻量注明“关联还在陆续补齐”；没有任何关联结果时明确说明。新安装且尚无图谱不可能立即提供完整关联，这个边界需要在原型与验收中真实出现。

性能验证覆盖 1,000 与 10,000 条记录、长短文、无标签记录、初次回填、增量积压、缓存命中／未命中、连续快速切换、弱网和中档手机。报告 p50／p95、样本数及测试环境，区分模型故障、网络故障与读取故障。还需核对后台任务不会使写入延迟明显回退。

## 10. 关联质量与默认范围

### 10.1 默认覆盖

- 本人已保存且同步、正常状态、未排除回顾／漫步的原记录自动进入来源池，含历史导入和无标签记录。
- 草稿、回收站、归档、其他人的记录、评论、系统生成结果、保存路线不进入发现来源池。
- 当天合格记录可以被关联或主动作为起点；随机起点适当偏向旧记录。每日回顾仍保持其既有日期规则。
- 首轮分析正文、记录日期、本人标签和已有连接。图片、原音、精确位置不自动送去识别；附件仍可按已有权限阅读。
- 纯媒体记录可沿已有明确连接阅读，不能凭空补出语义关系。
- 排除是全链路规则：不能让被排除的记录作为隐藏的过桥节点，再借主题名或提示泄露它的内容。

这是默认产品行为。设置中的暂停、单条排除和清理派生数据是控制出口，不要求用户每次选择标签或范围。

### 10.2 可解释而不过度解释

| 可呈现的联系 | 必要依据 | 不能直接推断 |
| --- | --- | --- |
| 同一问题 | 两条原文讨论可点名的问题 | 同标签就有共同立场 |
| 补充视角 | 情境、问题或经验可放在一起理解 | 一条必然是在回答另一条 |
| 不同说法 | 相近语境中明确不同的原话 | 日期先后就是成长、退步或因果 |
| 跨主题联系 | 不同场景中具体相似处，也保留差别 | 共通心理成因或人格诊断 |

短提示必须能被展开的准确摘录支持，引用绑定来源版本。通用的“都与情绪有关”不能作为凑数依据。观点矛盾可以保留，不需要系统替本人调和。

“这条联系不贴切”针对记录对和关联类型，跨会话记住；不能换种措辞立刻重推，也不能因来源轻微编辑自行清除否定。用户可以撤销。阅读、保存或停留都不自动等于本人确认关系成立。

### 10.3 处理服务的说明

自动建立全库关联需要实际可用的处理能力。部署／设置阶段清楚显示服务、处理内容和覆盖范围；若走外部服务，要如实说明合格正文会用于后台整理。正常漫步没有每次确认流程。

现有 chat-completions 配置不证明具备语义表示能力；也不能把曾经对几条记录的洞察调用，静默解释为允许将全部笔记送往任意新服务。技术选型需核实本地、自托管或外部路径的能力与成本，落实本次自动处理意图对应的具体服务配置。服务更换涉及新的数据接收方时在设置中说明变化，不伪造“全程本地”保证。

## 11. 生命周期与异常状态

| 状态或变化 | 用户可见行为 | 后台／缓存要求 |
| --- | --- | --- |
| 正常可读 | 原文、附近记录、收起的依据 | 直接读取已准备内容 |
| 初次建立／导入较多历史 | 原文与已就绪区域可读；覆盖不全时有轻量说明 | 断点续跑，不等用户进入才开始；不虚报全库已完成 |
| 空库／仅一条／无可信联系 | 明确相应状态；有原文就可阅读 | 不虚构主题或凑节点，不要求补写 |
| 模型服务故障或限流 | 仍有效的既有结果可读；更新延迟在状态入口可查 | 停止无上限重试；不因生成故障关闭已有阅读 |
| 有界读取失败／网络断开 | 保留当前仍可显示的阅读；待加载位置可重试 | 不把错误当成没有关联；恢复后重新校验资格 |
| 原文被编辑 | 显示最新原文；旧版本相关提示撤下 | 自动重新整理，不要求用户点击更新，不把旧解释配给新原文 |
| 删除、归档、排除或归属改变 | 相应节点、摘录、提示与派生主题内容退出可见结果 | 发布资格撤回并清理缓存；旧图谱版本也受撤回约束 |
| 主题部分来源失效 | 保留仍有依据的内容，必要时暂时隐藏主题名 | 不能只移除节点，却留下泄露来源的标题或推测 |
| 恢复原记录 | 正常原文恢复可读 | 重新计算有效派生结果，不复活旧撤回解释 |
| 停用自动关联 | 停止新处理，可继续基础原文回顾 | 可清除索引、主题和建议，保留原记录 |
| 登录失效／切换账户 | 清除私密显示并按身份重新进入 | 不复用上一账户的预取、原文与路径 |

普通版本更新可以继续读取仍有效的旧结果；来源撤回不能按普通缓存过期延迟处理。资格与内容版本是读取时的约束，不只是后台最终清理工作。

## 12. 首轮范围与下一阶段原型

首轮核心闭环：后台自动维护 → 无配置进入 → 原文与附近节点 → 一次点击继续 → 展开已有依据 → 返回／换起点 → 否定牵强联系。

首轮必须包含增量更新、来源撤回、冷启动和后台故障行为。不能只交付可点击地图，把后台准备与等待留到后面。

后续可增加：私密保存与重开路线、专题时间对照、更大范围鸟瞰、用户主动发起的深入洞察衔接。它们不作为当前每次漫步的必经动作。

完整原型使用虚构记录，覆盖：

1. 从任意入口直接遇见原文，主题作为周围线索，未打标签也能参与。
2. 爱情 → 家人 → 工作场景之间的逐步连接，原文优先、提示可展开。
3. 点击节点直接切换、快速连点、返回恢复、换起点。
4. 桌面并排阅读与局部图，320／390 像素手机阅读和可展开地图，键盘与减少动态效果。
5. 初次图谱未齐、无关联、来源编辑／撤回、预取未命中、断网与恢复。

v0.1 已交付的交互示意仅保留为“原文优先、提示展开”的历史讨论材料，其中两步继续流程不再代表本稿。该示意的布局与脚本检查不作为 v0.2 交互或性能验证。本轮没有制作新的可运行原型。

## 13. 可验收场景

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| AC01 | 日常进入 | 无标签／范围选择步骤，直接读到起点原文和有效邻近内容 |
| AC02 | 保存后离开应用 | 后台继续增量整理，保存不依赖模型完成；再次进入已有可读结果 |
| AC03 | 无标签与跨主题材料 | 能按具体问题提出有证据的联系，不被标签分类限制 |
| AC04 | 两个时期的不同说法 | 保留日期与语境，不自动宣布成长或人格结论 |
| AC05 | 切换、连点、返回、改道 | 一次点击改变焦点，最后操作有效，返回恢复位置与分支 |
| AC06 | 展开提示 | 直接显示准确、已准备的双方摘录；网络轨迹中没有临时模型生成 |
| AC07 | 无可信关系／孤立记录 | 仍能阅读；不补满配额，不使孤立记录永久不可遇见 |
| AC08 | 否定联系与撤销 | 跨会话有效，不换措辞立即重推，不修改手动关系 |
| AC09 | 新安装与大量历史回填 | 原文可先读，已就绪区域逐步可用；范围不足有说明，无虚假完成率 |
| AC10 | 模型故障、进程重启和限流 | 既有有效结果可读，后台可恢复且有界重试，不拖垮保存 |
| AC11 | 编辑、删除、排除、归档 | 旧解释与派生敏感内容失效，原文版本正确，来源撤回覆盖旧缓存 |
| AC12 | 首屏与继续浏览性能 | 按第 9 节分别测量冷／热／缓存未命中结果，报告环境和 p95 |
| AC13 | 浏览器数据获取 | 首屏与单步不扫描或传输全库；预取深度、条数与字节有界 |
| AC14 | 手机、键盘、减少动态效果 | 可读、可选路、可返回，无横向溢出或只可拖拽的路线 |
| AC15 | 登出、切换账户、断线恢复 | 私密内容按资格清理，恢复前重新核对来源版本 |
| AC16 | 服务配置与停用 | 数据处理说明符合实际；停用停止新处理，清理派生数据不伤原记录 |

质量验证先用受控合成材料覆盖同义、重复、相反观点、不同主体、无关联和长短文；真实记录的样本与处理服务在后续实施中明确。工程指标与本人对“有意义、有意思”的评价分别记录。
